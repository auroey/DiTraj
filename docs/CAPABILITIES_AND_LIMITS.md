# 功能与边界

本文依据本仓库保留的上游 Wan 实现和新增的 [低显存入口](../repro/run_low_vram.py)。区分“代码可表达”“入口已开放”“实际运行验证”，不把论文展示效果等同于本仓库已经验证的能力。

## 能做什么

| 功能 | 上游代码 | 当前低显存入口 |
| --- | --- | --- |
| 文本生成视频 | 读取 `base_prompt`、`fg_prompt`、`bg_prompt`，默认 Wan2.1-T2V-1.3B | 支持 JSON 和条目索引；不需要先运行 Qwen |
| 单目标轨迹 | 一个前景 bbox 随时间移动，前景/背景分别接受文本条件 | 支持，但轨迹固定为等尺寸框从左向右移动 |
| 多关键帧、折返、分段轨迹 | 四个框边界分别做分段线性插值；可用关键帧近似曲线 | 尚未开放自定义轨迹参数 |
| 变尺寸、变长宽比 bbox | 代码包含动态框 RoPE 缩放分支 | 固定轨迹不覆盖此功能，未完成此类复现验证 |
| 多物体独立控制 | 没有对象 ID、多条独立轨迹及各对象 prompt 映射 | 不支持；画面出现多个物体不等于可分别控制 |
| 图片/视频输入、原视频编辑 | 公开入口为文生视频，无图片/视频条件入口 | 不支持 |
| 深度、3D/4D、换视角重拍 | 没有深度图、世界坐标、相机位姿或可编辑场景资产接口 | 不支持 3D/4D 重建、场景重渲染或相机轨迹控制 |
| 输出 | RGB 视频及叠加输入 bbox 的视频 | MP4、`_box.mp4`、运行参数与资源统计 JSON；没有音频或 3D 资产 |
| 训练、评测、交互 UI | 免训练推理；未提供完整训练或论文指标评测脚本；Gradio 仍是 TODO | 无新增训练/评测/UI 功能 |
| 其他模型 | README 提到可适配其他 DiT；仓库实现集中于 Wan | `--model` 可指定路径不代表任意模型兼容；14B、CogVideoX 未在本次复现中验证 |

论文中的 “3D-aware” 指用二维 bbox 的大小变化引导接近/远离等外观效果，不是显式三维几何控制。“3D RoPE”的三个轴是视频的时间、高度、宽度。[论文](https://arxiv.org/abs/2509.21839)的跨模型实验也不等于仓库已有相应运行入口。

代码依据：[run.py](../run.py) 第 56–74、95–134 行；[utils.py](../utils.py) 的 `plan_path`；[pipe.py](../module/pipe.py) 第 37–55、157–178、296–317 行；[transformer_wan.py](../module/transformer_wan.py) 第 531–554 行；[README](../README.md) 的 ToDo。

## 输入与参数约束

### 低显存入口已经实施的检查

以下是显式检查，不是所有底层依赖约束的完整集合。`F` 表示输出帧数，`H/W` 表示输出高度/宽度。

| 项目 | 约束或实际行为 | 默认值 |
| --- | --- | --- |
| 帧数 | 整数，`F >= 5` 且 `(F - 1) % 4 == 0` | 81 |
| 空间尺寸 | `H/W >= 64`，均为 16 的倍数；还须通过下面的小框检查 | 480 × 832 |
| 框的有效尺寸 | 在每个采样帧上，取整后的框宽、高均至少为 2 个控制 token | 由固定轨迹决定 |
| 推理步数、FPS | 正整数 | 50 步、20 FPS |
| 控制截止步 | `mask-step`、`fix-rope-step` 为非负整数；0 关闭对应阶段的使用，达到或超过总步数则全程使用 | 30、5 |
| Prompt JSON | JSON 列表；索引非负且存在；选中条目应为对象，包含三个非空字符串字段 `base_prompt/bg_prompt/fg_prompt` | 随仓库提供的示例第 0 项 |
| 输出 | 扩展名为 `.mp4`；主视频、框线视频或同名统计 JSON 任一已存在即拒绝覆盖 | 必须指定 |
| 运行环境 | Diffusers 0.33.1、作者替换版 transformer、恰好一张可见 NVIDIA CUDA GPU | CPU model offload |

“尺寸至少 64”只是第一层校验：例如小分辨率可能使固定框取整后不足两个 token，不能据此声称 64×64 可运行。小框检查在模型加载后执行；`--dry-run` 不会执行它，也不验证 CUDA、依赖兼容性或真实显存占用。现有 [单元测试](../tests/test_run_low_vram.py) 不运行模型或 GPU。

当前入口还开放 `--seed`、`--model`、`--local-files-only` 等选项；CFG 固定为 5，负面提示词从上游代码读取，没有自定义轨迹或 CFG 的 CLI。VAE 使用 FP32，主模型使用 BF16；固定依赖版本的 Wan VAE 没有空间 tiling API。依据：低显存入口的 `parse_args`、`trajectory_for_frames`、`main`。

### 自定义上游轨迹的必要条件

这些条件用于安全使用上游 `--bboxs_arg`，并非上游已完整实现的输入校验；低显存入口目前不接受该参数。

- 每个关键帧是 **`[frame, y1, y2, x1, x2]`**，不是 `[frame, x1, y1, x2, y2]`。坐标应为有限的归一化数值，满足 `0 <= y1 < y2 <= 1`、`0 <= x1 < x2 <= 1`。
- 使用至少两个关键帧，帧号严格递增，首帧为 0、末帧为 `F-1`。重复帧会除零；首尾未覆盖时，`utils.py` 第 45、51 行的外推把标量拼入路径列表，破坏数据结构。当前固定轨迹避开了这个问题。
- 四个边界分别线性插值，所以位置、宽度、高度都可变化；没有样条、物理速度约束或独立深度坐标。
- `run.py` 第 102 行每隔 4 个输出帧采样控制；空间网格为 `H/16 × W/16`，坐标转为整数。不能承诺逐像素、逐输出帧的任意精细控制。
- 空框、出画后完全不可见、极小框不是已支持的状态。RoPE 的框角点包含最后一个占用位置，但后续切片把它作为不包含的终点，会少覆盖底/右边缘；极小框存在空切片或动态缩放问题（`transformer_wan.py` 第 525、548–554 行）。

上游 pipeline 会调整不符合时间压缩要求的帧数，但外部 mask 已提前构造，不能依赖该调整修复错误输入。当前入口直接拒绝不合规帧数。

### 其他不能从接口签名推导的能力

- 实际按单视频、batch=1 使用。虽然 pipeline 签名包含批量参数，`transformer_wan.py` 第 582 行的 `int(timestep.data)` 对多元素 timestep 不成立。
- 默认每段文本编码长度为 512 tokens；控制阶段拼接背景、前景两段为 1024 tokens，mask 也固定为该长度。不是 512 个字符；不能仅修改文本长度而不同时适配 mask。
- 两个控制截止步设为 0 仍会构造前置控制 mask（`pipe.py` 第 337–344 行），不等于消除其显存开销。
- FPS 改变播放速度，不增加生成帧数。81 帧、20 FPS 约为 4.05 秒。上游导出使用 `F//4` FPS，低显存入口允许单独指定 FPS。
- `_box.mp4` 叠加的是**输入指令框**，不是检测到的目标框。统计 JSON 的帧均值/标准差不是轨迹命中率、身份一致性或视频质量指标。

## 已验证范围与未知上限

已经完成的完整运行配置为：Wan2.1-T2V-1.3B、81 帧、480×832、50 步、单张 RTX 4090、CPU model offload。它是一个已运行的配置点，不是最小硬件要求、最大可用尺寸或论文全部实验的复现。

尚未建立以下边界：最长视频、最高分辨率、最大可用步数、最小可控目标、最快可靠运动、遮挡/身份保持、多个物体干扰，以及不同 prompt/种子的成功率。14B、720P 和变尺寸/复杂轨迹也不能列作本次已验证配置。更低步数成功输出不代表达到论文质量。

资源增长可从代码估计，但估计不是实测上限：

```text
N = ((F - 1) / 4 + 1) × (H / 16) × (W / 16)
单个持久布尔自注意力控制 mask ≈ N² bytes
```

默认配置 `N=32760`，仅这个 mask 约 1 GiB，尚未计入模型、临时 mask、注意力、VAE、CPU offload 和视频导出内存。token 数翻倍，该项约增至四倍；不能按帧数或像素数线性推算总显存。RoPE 缓存等底层实现还有自身尺寸约束；CLI 没有显式最大值不表示无限可用。跨软件版本/硬件的逐像素确定性也没有验证。
